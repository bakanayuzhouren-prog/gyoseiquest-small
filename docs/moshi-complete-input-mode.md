# 模試完全インプットモード設計

## 目的

全60問の模試を、問題画像・解答画像から端末内に取り込み、断片的な暗記ではなく横断的な理解状態を見える化する。

このモードは次を目指す。

- 問題・解答・解説画像をOCRし、問番号ごとに構造化する。
- 科目・分野別に、理解済み・誤答・未確認を可視化する。
- 合格レベルに対する現在地を10段階で判定する。
- 判定レベルに応じて、次にインプットすべき知識を変える。
- 誤答論点を `君の教科書！` に渡し、自分用の教科書章を生成する。

## 初版で実装した範囲

- ルート: `app/moshi-input.tsx`
- 解析ロジック: `utils/moshi-complete-input.ts`
- メニュー導線: `app/(tabs)/index.tsx`

初版では、既存依存だけで実装できる範囲として、Web/PCで画像を選択し `tesseract.js` でOCRする。
スマホ直撮りは `expo-image-picker` または同等の追加依存が必要なため、次フェーズで実装する。

## データの扱い

市販模試の問題文・解説は著作物なので、リポジトリの固定データに入れない。

- 保存先: `AsyncStorage`
- 保存キー: `gq_moshi_complete_input_latest`
- 用途: てらしぃ本人の端末内学習
- 禁止: 模試本文・解説全文を `src/`, `data/`, `docs/` に固定保存して配布可能状態にすること

## 10段階判定

| Level | 意味 |
|---|---|
| 1 | 見て聞いて覚えるところから始める段階 |
| 2 | 用語はあるが、正誤判断の要件に結びついていない |
| 3 | 基礎語句に穴があり、横断比較前の補強が必要 |
| 4 | 基本論点を固める段階 |
| 5 | 基礎はできているが、形を変えて出題されると対応できない |
| 6 | 合格ラインへ押し上げる段階 |
| 7 | 合格ライン目前。取りこぼし防止が重要 |
| 8 | 合格安定圏。新法・改正・判例で差がつく |
| 9 | 上位合格を狙う段階 |
| 10 | 司法試験合格レベル級。制度趣旨・判例射程まで見えている |

初版の判定は、問ごとの正解・誤答マーキングから正答率をもとに算出する。
今後は、問題難度、科目配点、記述式、多肢選択、過去の推移を加味する。

## 次フェーズ

1. スマホ直撮り対応
   - `expo-image-picker` などでカメラ・画像ライブラリから取り込む。
   - 複数画像の順序入れ替え、ページ番号補正を入れる。

2. OCR確認UI
   - 問番号・選択肢・正解・解説を1問ずつ確認する。
   - OCRミスをその場で修正する。

3. 模試を解くモード
   - 60問を本番形式で解答する。
   - 時間、迷った肢、正誤、メモを保存する。

4. 君の教科書！連携
   - 誤答問を `君の教科書！` の章生成元にする。
   - 「TAC第2回 問17 訴えの利益」など、模試問番号単位でリンクする。

5. 横断知識マップ
   - 例: 行政手続法の聴聞、弁明、意見公募、理由提示を1表に束ねる。
   - 例: 民法の第三者概念、時効、相殺、詐害行為取消を横断する。
